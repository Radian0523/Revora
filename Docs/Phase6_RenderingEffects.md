# Phase 6: 描画演出の実装メモ

## 概要

Lambert ライティングのみだった描画に、シャドウマップ・環境マップ反射・半透明描画・パーティクルエフェクトを追加した。

## 実装内容

### 1. シャドウマップ (ディレクショナルライト)
- 2048x2048 の D32_SFLOAT 深度テクスチャを使用
- 正射影 (100x100m) でコース全体をカバー
- 深度バイアス + フラグメントシェーダー側のバイアスで shadow acne を防止
- 3x3 PCF カーネルでソフトシャドウを実現
- GraphicsDevice を BeginFrame/BeginMainPass に分割し、シャドウパスをメインパスの前に挿入

### 2. 環境マップ反射
- 既存のスカイボックスキューブマップを環境マップとして再利用
- Schlick の Fresnel 近似で浅い角度ほど反射が強くなる効果を再現
- reflectivity パラメータで反射率をオブジェクトごとに制御 (車両: 0.3, コース: 0.0)

### 3. ゴースト半透明描画
- MeshRenderer に半透明パイプライン (SRC_ALPHA / ONE_MINUS_SRC_ALPHA) を追加
- 深度テスト有効・深度書き込み無効で、不透明オブジェクトの後に描画
- alpha=0.4 でゴースト車両の半透明感を表現

### 4. パーティクルシステム
- ParticleEmitter (Game 層): 生成・更新・寿命管理をオブジェクトプールで実装
- ParticleRenderer (Engine 層): ビルボードクアッドの加算ブレンド描画
- タイヤスモーク: 後輪スリップ比 > 0.7 && 接地中で白煙を発生
- 壁衝突火花: 衝突速度 > 2.0 m/s で黄/オレンジの火花を発生

## 設計判断の理由

### MeshRenderer の独自ディスクリプタ管理
- 既存の DescriptorSetManager は UBO + サンプラーの 2 バインディング固定で、Skybox と共用
- シャドウマップと環境マップの追加で 4 バインディングが必要になったため分離
- Skybox は既存の 2 バインディングレイアウトを変更なしで使い続けられる

### GraphicsDevice の BeginFrame/BeginMainPass 分割
- シャドウパスはメインレンダーパスの外で実行する必要がある
- 従来の BeginFrame がレンダーパス開始を含んでいたため、分割して間に別パスを挿入可能にした
- 将来のポストエフェクトパス追加にも対応できる設計

### パーティクルのビルボード方式
- ジオメトリシェーダーを使わず、gl_VertexIndex からクアッドを展開する方式を採用
- MoltenVK (macOS) でジオメトリシェーダーのサポートが不安定なため互換性を優先
- インスタンス描画で全パーティクルを1ドローコールで描画

## 他の選択肢と不採用理由

- **カスケードシャドウマップ**: コース半径が限定的 (50m) なため単一の正射影で十分
- **Screen Space Reflection**: 実装コストが高く、キューブマップ反射で十分な品質が得られる
- **GPU パーティクル (コンピュートシェーダー)**: パーティクル数が少ない (最大 384 個) ため CPU 更新で十分
